## PART 1 — TRANSITS

### 1.1 Output – Transit fit page: layout and controls (transit_ui.py `TransitPage.__init__`, ~L102–315)

The page is the Output page while the app is in **Transits** mode (built by App in clearv_app.py; see 2.5 for mode/view switching). Heading label: **"Output – Transit fit"**. Directly under it a hint line shows the current planet summary (`planet_summary`, L63): e.g. `K2-113 b   P 5.817640 d   T14 3.21 h   depth 0.98%   Rp/R* 0.0990   a/R* 12.30   b 0.45   (NASA Exoplanet Archive)`; with no planet it reads *"No planet yet: enter one on the Input page (Planet, Lookup) or open an exoplanet report."*

Rows, top to bottom:

**Row 1 – source**
- "Night" — read-only Combobox listing nights of the current photometry, labelled like `K2-113 b · night of 5–6 Oct 2026` (JD key kept behind; duplicates get ` (JDkey)` suffix). Picking a night drops any loaded report and any trim, clears the fit, and (if the data are fresh) auto-fits (`_night_picked`/`_use_night` L339/430). Newest night is selected by default.
- "Open AAVSO exoplanet report (EXOTIC)…" — Button; file dialog titled "AAVSO exoplanet report" (`*.txt`). Loads an EXOTIC/AAVSO exoplanet text report and fits its light curve (see 1.4).
- "Close report" — Button, appears right after the Night box only while a report is loaded; returns to the newest photometry night (`close_report` L345). If no photometry is loaded, notes say *"Report closed. Run photometry in Transits mode, or open another report."*
- Hint text at the right of the row (`source_text`): for photometry `"{n} usable points on {night}; {m} in this fit ({k} flagged put back), {t} trimmed"` (`_count_text` L446); for a report `"{file}: {n} points, {SOFTWARE}, {date}"`.

**Row 2 – fit settings**
- "Detrend" + Checkbuttons "airmass" (default on) and "time slope" (default off) — detrending terms multiplied into the model.
- "MCMC" read-only Combobox: "Quick (1,500 steps)", "Standard (3,000 steps)" (default), "Thorough (8,000 steps)" (`MCMC_CHOICES` L29).
- "Fit transit" — accent Button; runs the fit on the shown source (`fit` L723).
- "Cancel" — Button; `app.cancel_job` stops the fit (or the comp check).
- "Refit with flagged frames (errors ×2)" — Button; appears only after a fit of a *photometry* night that has cloud-flagged frames the fit left out (`_show_refit_flagged` L408; factor is `tc.FLAGGED_ERR_FACTOR`). Puts the cloud/cloudedge/haze-flagged frames back with error bars doubled and refits (`fit(with_flagged=True)`). Never shown for a report.
- "meridian flip at the largest gap" — Checkbutton; appears only while a report is loaded (and `tc.FLIP_STEP_ENABLED`). A report has no flip segment; ticking it tells the fit to treat the middle of the largest time gap as the meridian flip (allows a flip step term). If SHOBS-P itself wrote the report, the flip time is read from the report's NOTES instead (`tc.report_flip_time`), `_data` L628–637.

**Row 3 – tools**
- "Tonight's transits…" — opens FinderWindow (1.9).
- "Transit planner…" — opens PlannerWindow (1.9).
- "Nearby-binary (NEB) check…" — opens NebWindow (1.9, brief).
- "Comp health…" and "Use comps…" — Buttons (2.2.17 item 4) opening the same comp windows as Variable View; a change in Use comps refits the transit automatically (1.5). A hint label beside them (`comp_hint`) explains when they are disabled.

**Row 4 – Trim** (2.2.17 item 5)
- "Trim" "from" Entry (width 13), "to" Entry — local clock times (or BJD) bounding a span to leave out; Enter in either box = Trim and refit.
- "Trim and refit" — Button. "Clear trim" — Button. Hint label (`trim_text`) says what is trimmed. You can also drag a span across the plot (1.5).

**Heads area** (above the plot, only takes room when non-empty, `_show_heads` L1361):
- banner (bold brown) — says what is being fitted when a report is loaded: *"Fitting {EXOTIC report / AAVSO exoplanet report}: {planet}, {date}, {n} points from {file}. Your {target} photometry is kept; choose its night above (or Close report) to go back."* plus any time-system note (`_show_source` L363). The Input page also gets a note *"The Transit fit page is showing … for {name}, not the photometry set up here."* (`app.set_report_note`).
- verdict line (bold, 11pt) — see 1.4.
- quality line — `quality_text` L84: `"Fit rms 0.480% per point · 0.210% per 10-min bin · 68 points · red-noise β 1.12 · χ²ν 1.05 (raw errors)"`.

**Body**: matplotlib plot (two panels: light curve + model, residuals; `draw` L1382) with a strip beneath: a parameter Treeview (8 rows visible, scrollable) with columns "Parameter", "SHOBS-P (MCMC)", "Free shape", "Published / prior", and "EXOTIC report" (last column only while a report is loaded, `_set_columns` L1047), and a read-only notes Text to the right (cautions in orange, info in grey; a blue underlined link opens Comp health). Notes pane is hidden when there is nothing to say.

**Progress row** (above Results, shown only while a fit/comp check runs or has a message): Progressbar + text `"Least-squares fit…"`, `"MCMC burn-in 600 of 1,000"`, `"MCMC step 1,200 of 3,000"`, then `"Done: Tc … ± …, Rp/R* … ± …, MCMC acceptance 0.xx"`, then `"Checking comps (1 of 3)…"` and `"Comps checked: depth spread 0.12 %, Tc spread 45 s (⚠ C2)"`.

**Results row** (bottom): label "Results", then Buttons "Save AAVSO exoplanet report…" (accent), "Open AAVSO Exoplanet Database…", "Save ExoFOP package…", "Open ExoFOP…", "Save light-curve CSV…" (`app.save_csv`, the general CSV), "Save plot PNG…", and at far right "Variable View  ▶" (accent; `app.show_variables_view`, switches the Output page to the Variables/photometry view). Details in 1.7.

Plot placeholder before any fit: *"No transit fit yet: pick a night or open an exoplanet report, then Fit transit."*

### 1.2 Fit flow, auto fit, stale fits (`refresh` L318, `_check_stale` L479, `fit` L723, `_finish_fit` L994)

- **Auto fit**: when the page is opened (or a night picked / report loaded) with ≥20 usable points, a planet known, and no fit yet, the fit starts by itself (`_check_stale(auto=True)` → `fit(auto=True)`), logging *"Transit fit: starting by itself on the new photometry / loaded report (Cancel stops it)."* With no planet the notes say *"Photometry is ready. Enter the planet on the Input page (name, then Lookup) and come back: the fit then runs by itself."* Fewer than 20 points: silently no auto fit.
- **Stale fit**: the fit's "signature" (night, point count, mags, comps, planet summary, scintillation setup, trims) is compared on every refresh; if the data changed, the fit is cleared and notes warn *"The photometry, the comps, or the planet changed since the last fit, so that fit was cleared. Fit transit to fit the data as they are now."*
- If a fit finishes after the source changed: progress says *"Fit finished for data no longer shown; not used."* and notes *"That fit was for data no longer on this page. Fit transit fits what is shown now."*
- **Pre-fit errors** (`_data` L616): photometry with <20 usable points → *"{night}: {n} usable points. Run photometry in Transits mode first (or open an exoplanet report)."*; missing site lat/lon → *"Enter your site's latitude and longitude on the Input page first (they are needed for BJD times)."* Shown as an error box when the user pressed Fit, as an info note when automatic.
- Pressing Fit transit with no planet: info box *"Enter the planet on the Input page first (name, then Lookup), or open an exoplanet report."*
- Pressing Fit while the comp check is running: status line *"Still checking the comps (a few seconds); Fit transit again when it is done, or Cancel the check."* While a report's ephemeris lookup is pending: info box *"Still looking up this planet's ephemeris; the fit starts by itself as soon as it is in."*
- **No-transit preview / "Fit anyway?"** (`fit` L760–787, `tc.transit_window_check`): if no predicted transit overlaps the data: text *"No transit of {planet} is predicted during these data. The nearest predicted transit is {h} h after the last point (Tc … BJD_TDB). A transit fit cannot measure anything here; if this was a variability run, use Variables mode."* Auto fit: shows a preview plot of the raw flux with an arrow annotation (*"Nearest predicted transit: 3.2 h after the last point →"*) and notes the warning plus *"Fit transit fits it anyway."* Manual fit: Yes/No box with the text + *"Fit anyway?"* — **Yes** runs the fit regardless; **No** shows the preview and warning.
- Fit runs in a background thread; `app._start_job("Fitting the transit…")`; limb darkening band comes from the night's filter (Sloan SG/SR/SI/SZ supported, 2.2.17 item 1).
- Failure: progress "Fit failed.", error box *"Transit fit failed: {reason}"*, traceback to log. Cancel: progress "Cancelled.", placeholder *"Not fitted yet: press Fit transit."*
- Success: progress "Done: …", log line with Tc, Rp/R*, depth, b, beta; status "Transit fit done."; table, notes (`tc.cautions`), plot redrawn; comp-noise warning from `core.comp_noise_warning` inserted as a caution; a loaded report's time-system note appended; trim text appended; each fit gets a serial (`_FIT_SERIAL`) used for numbered save sets.

### 1.3 Leave-one-comp-out check (`_start_comp_check` L905, `_comp_check_done` L947; `tc.leave_one_comp_out`)

Right after a successful photometry fit with ≥2 comps (never for a report, never when verdict is "none"), SHOBS-P refits once per comp with that comp left out (least squares). Progress row shows `"Checking comps (j of m)…"`; Cancel stops it (log "Comp check cancelled.", status *"Transit fit done; comp check cancelled."*). On completion the result's flags gain the check's cautions, notes are redrawn, the progress text appends `"Comps checked: depth spread x.xx %, Tc spread n s (⚠ comp names / comp choice)"`, status *"Transit fit done; comps checked — see the caution in the notes."* The result (`comp_loo`) is written into the fit files/package. Pitfall: pressing Fit transit during the check is refused (status line) — wait or Cancel.

### 1.4 Verdict line, quality line, table, notes, plot (`_show_verdict` L1210, `_fill_table` L1251, `draw` L1382)

**Verdict** (`result["verdict"]`, states via `_state`: detected / inconclusive / none):
- detected: green `"✓ {reason}"`; if depth_unreliable, orange `"✓ {reason} Timing usable; depth unreliable: {why}."`
- inconclusive: orange `"⚠ {reason} Tc may be usable; the depth is not."` (or *"Neither Tc nor the depth is measured."* when the flip step is the cause).
- none: red `"✗ No transit measured. {reason} The numbers below are for reference only."` Table rows then grey out.
- A fit that put flagged frames back is prefixed `"[includes N cloud-flagged frames] "` (verdict `includes_flagged`).
- Plot title mirrors it: `"{planet}   Tc … ± … BJD_TDB"`, `"{planet}   INCONCLUSIVE   Tc …"`, `"{planet}   NO TRANSIT MEASURED (model shown for reference)"`, plus `"incl. N flagged"` and `"({source})"` (night key or report file).

**Quality line**: `"Fit rms x.xxx% per point · x.xxx% per 10-min bin · N points · red-noise β x.xx · χ²ν x.xx (raw errors)"`. χ²ν is reduced chi-square against the *raw* per-point errors; a value well above 1 means the photometric errors are underestimated (scintillation / comps); the cautions from `tc.cautions` say so in words (see 1.8 for the χ²ν messages).

**Table rows** (Parameter / SHOBS-P (MCMC) / Free shape / Published / prior / {Report}): "Tc (BJD_TDB)", "O − C (min)" (after a fit; Published column shows "0"), "Rp/R*", "Depth (%)", "a/R*", "Impact parameter b", "Inclination (°)", "Duration T14 (h)", "Limb darkening u1"/"u2", "Airmass slope"; with a flip step: "Flip step (%)", "Depth without step (%)", "Step–depth correlation"; then "rms per point (%)", "rms per 10-min bin (%)", "Red-noise beta", "Reduced χ² (raw errors)", "Points". Values `"x ± y"`. Orange-tagged rows are those a caution names (a/R*, b, grazing, shape left free, flip depth not ok). "Free shape" is a least-squares fit with the shape left free (`free_fit`), for comparison with the prior-constrained MCMC result. "Published / prior": the lookup's values; Depth here is (Rp/R*)² (2.2.13). The report column heading is `"{SOFTWARE} report"` e.g. "EXOTIC 4.3.2 report" or "SHOBS-P 2.2.16 report", else "Report" (`_report_column` L1926).

**O − C**: `(fitted Tc − predicted Tc) × 1440` min, ± hypot(Tc error, predicted-Tc error). Predicted Tc (`tc_pred`) comes from the planet's ephemeris (t0, period) — see 1.8 for the source.

**Notes pane**: cautions from `tc.cautions(flags, verdict)` ("⚠ " = warn, "• " = info). A comp-choice caution (comp-noise warning, leave-one-out cautions, `COMP_CAUTION_PREFIXES`) ends with a clickable link (`COMP_LINK`) that opens Comp health, when this session's photometry is shown.

**Plot** (`draw`): grey dots "each frame, detrended"; hollow orange circles "flagged cloud (errors ×2)" when flagged frames were put back; black "10-minute bins" with error bars; green model line labelled `"SHOBS-P: Rp/R* … ± …, depth …%"`; blue dotted `"published shape: Rp/R* …, b …"` when the lookup gave k, a/R*, b; pink dashed `"{EXOTIC/SHOBS-P}: Rp/R* …, b …"` for a report's own result; grey dashed vertical line + shaded band = predicted Tc ± its error; thin green verticals = fitted T14 edges; purple dash-dot line + `" flip: step +0.3 ± 0.1%"` at the flip time; grey shaded "trimmed (not fitted)" spans with faint × points. Lower panel "Resid. %". X axis "Hours from fitted mid-transit"; the range covers the data plus the fitted transit (never stretched to a far predicted Tc). Preview mode (no transit predicted): single panel, "Hours from the first point (HH:MM local)" with the arrow note in orange.

### 1.5 Comp health… / Use comps… with auto refit; Trim (2.2.17 items 4, 5)

**Comp buttons** (`_comp_windows_ok` L1550, `_update_comp_buttons`, `comps_changed` L1587): enabled only when this session's photometry (a night) is shown. Disabled with hint *"Comp health and Use comps are for this session's photometry: choose its night above (or Close report)."* (report shown while photometry exists) or *"Comp health needs this session's photometry."* (no photometry). They call `app.show_comp_health()` / `app.choose_comps()` (same windows as Variable View). After Use comps applies a new set in Transits mode the App calls `comps_changed`: if a fit/comp check is running, notes say *"Comps changed (now C1, C3): the transit is refitted with them as soon as the running fit/comp check ends."* and the refit follows automatically (`_run_pending_refit`); otherwise the stale fit is cleared and refitted at once when the page is on screen (*"Comps changed (now …): refitting with the same settings…"*), or when the page is next shown. While a report is shown nothing happens (the photometry refits when its night is chosen again).

**Trim** (`trim_and_refit` L1796, `clear_trim` L1841, `_span_dragged` L1855):
- Default hint: *"local time (HHMM or HH:MM) or BJD_TDB; or drag across the plot"*. Boxes accept local clock time (`parse_clock`, e.g. `0042`, `00:42`, taken on the date nearest the middle of the data), a full JD `24xxxxx.x`, or a reduced JD `6xxxx.xxx`. Empty From = from the start; empty To = to the end.
- Dragging horizontally across the fitted plot (matplotlib SpanSelector, min 30 s) fills From/To with HH:MM and keeps the exact BJD behind them; status *"Trim span 22:10–22:31 (14 points) marked: Trim and refit leaves it out."* Dragging works only on a fitted plot.
- "Trim and refit": refuses while busy (status *"Wait for the current fit or check to end, then Trim and refit."*); both boxes empty → info *"Type a From and/or To time (local, HHMM or HH:MM, or BJD_TDB), or drag across the plot, then Trim and refit."*; bad text → error *"Trim: {reason}"*; From after To → *"Trim: From (a) is after To (b)."*; no points inside → *"No points fall between From and To: nothing to trim."*; too few left → *"That trim would leave N points; a transit fit needs at least 20."* Spans accumulate (each Trim and refit adds one). Then refits with the same comps (no new reduction). Log: *"Transit fit: trimming N points (a to b) and refitting."*
- "Clear trim": with nothing trimmed clears boxes, status *"Nothing is trimmed."*; otherwise drops all spans and refits all points.
- After the fit, hint shows *"Trimmed: 22:10–22:31 (14 pts)"* or *"Trimmed: 2 spans, 30 pts (see the notes)"*; before the refit *"1 trimmed span set; Fit transit applies it."* Notes carry the full text *"Trimmed: … local (BJD_TDB …–…, N points) (k cloud-flagged frames there are left out too). These N points are left out of the fit, the verdict, the rms, the comp check and the saved files; Clear trim puts them back."* — plus *"Local times are approximate (±8 min: the report's star position is not known)."* for a report whose star is unknown. The report NOTES get `"SHOBS-P: trimmed (left out of the fit) BJD_TDB …-… (HH:MM-HH:MM local, N points)"`.
- A trim belongs to its source: picking another night, opening/closing a report, or re-running photometry (series generation changes) clears it (log *"Transit fit: the series changed, so the trim was cleared."*).

### 1.6 Opening EXOTIC / AAVSO exoplanet reports (`open_report` L522, `_report_time_system` L1508, `_find_ephemeris` L567)

- File dialog "AAVSO exoplanet report" (*.txt). Parse errors → *"Could not read {file}: {exc}"*. The report's planet (`tc.planet_from_report`) is used unless the Input page names the same planet with a period.
- The old plot clears at once with placeholder *"{planet}, {date}, {n} points from {EXOTIC x.y}: fitting…"* (or *"looking up the ephemeris…"*, or *"press Fit transit when the current job ends"*). Notes: *"Report loaded and being fitted. SHOBS-P refits its light curve and lists the report's own results ({writer}) beside SHOBS-P's. Cancel stops the fit; Fit transit runs it again with other settings."*
- **Ephemeris for a report without one** (no QC-XC line): background lookup, NASA Exoplanet Archive first (`tc.lookup_planet`), then an EXOTIC `inits` file beside the report (`tc.ephemeris_from_inits`); never from the lowest point. Log *"Transit fit: the report has no ephemeris; using {source}."* or *"…none was found ({why}); no O − C will be given."* The fit starts when done.
- **Time systems** (`#DATE_TYPE`): BJD* → as is. HJD* → +69.184 s to BJD_TDB; note *"The report's times are HJD_UTC; SHOBS-P moved them to BJD_TDB (+69.184 s; good to a few seconds)."* JD* with a known star position (Input page or lookup names the same star) → converted; note *"The report's times are JD_UTC; SHOBS-P converted them to BJD_TDB."* JD* with unknown position → kept, banner/notes warn *"⚠ The report's times are JD_UTC, not BJD_TDB, and the star's position is not known (enter the star on the Input page and open the report again): Tc is in JD_UTC, up to ±8 min from BJD_TDB, with no usable O − C."* and saved files get the note *"SHOBS-P: times are JD_UTC from the source report (not converted; star position unknown)"*. Anything else → *"⚠ The report's times are {X}, which SHOBS-P does not convert; it fits them as BJD_TDB, so Tc may be off."* The report's own Tc/ephemeris are shifted along with the points.
- Banner (bold brown above the plot): *"Fitting EXOTIC report: WASP-12 b, 05-OCT-2026, 210 points from AAVSO_WASP-12b.txt. Your K2-113 b photometry is kept; choose its night above (or Close report) to go back."* `report_kind` (L2407) names it "SHOBS-P report"/"EXOTIC report"/"AAVSO exoplanet report" by #SOFTWARE.
- The report's results appear in the right-hand table column and as a pink dashed model on the plot. Comp health/Use comps, Refit with flagged, and the comp check are unavailable for a report; the "meridian flip at the largest gap" box appears instead.
- Pitfall: the Input page still shows your own target; the Input-page note says the Transit page is showing the report. Close report (or pick a night) to go back.

### 1.7 Results row: saves, uploads, ExoFOP package (`save_aavso` L2080, `save_png` L1980, `save_package` L2164, `open_exofop` L2124)

Common guards: any save with no fit → info *"Fit a transit first."*; while the comp check still runs → info *"The comps are still being checked (a few seconds). Save the {AAVSO exoplanet report / ExoFOP package / plot PNG} when that is done, so it carries the comp-choice result."* (`_still_checking`). The report and package also pass `_confirm_export` (L1236):
- verdict none → Yes/No *"This fit did not measure a transit: {reason} A report from it would carry numbers that mean nothing. Save it anyway (for your records, not for submission)?"*
- inconclusive → Yes/No *"This fit is inconclusive: {reason} The report will say so in its notes. Tc may be worth reporting with that caveat; the depth is not. Save it?"* (or *"Neither Tc nor the depth is measured (the flip step trades off against both)."*).
- No cancels the save.

Where files go (`App.output_path` clearv_app.py L1506): into the Input page's output folder when one is set (never overwriting; `family=True` means the AAVSO report, light-curve CSV and plot PNG of one fit share one `_N` suffix, `_family_path` L1476; a new fit starts a new numbered set because `_results_key` includes the fit serial); with no output folder a Save-as dialog opens with the suggested name. After a save with an output folder the status bar says *"Saved {file} to {folder}."*; without one an info box *"Saved {path}"* (`saved_notice`).

- **"Save AAVSO exoplanet report…"** — writes `AAVSO_<planet>_<DD-MON-YYYY>_SHOBS-P.txt` (`family_names` L1931; planet name with spaces removed, e.g. `KELT-16b`), ASCII, via `tc.aavso_exoplanet_report`. NOTES carry the verdict when not detected (`SHOBS-P verdict INCONCLUSIVE: …`), the depth-unreliable note, trim note, flip note, flagged-frames note, JD_UTC note (`_file_meta` L1944). Then status *"Saved {file} — upload to the AAVSO Exoplanet Database (check its current instructions):"* with a status-bar link button "Open AAVSO Exoplanet Database…" (`offer_upload`).
- **"Open AAVSO Exoplanet Database…"** — opens https://apps.aavso.org/exosite/submit in the browser; status *"Opened the AAVSO Exoplanet Database's submit page in your browser."* or *"Could not open a browser: go to {url}"*.
- **"Save ExoFOP package…"** — asks for a folder only when no output folder is set ("Folder for the ExoFOP package"). Writes a *folder* (no zip since 2.2.16) named `ExoFOP_<planet>_<YYYYMMDD>_<obscode|obs>_SHOBS-P` (date = UTC date of the first point, trims included; a second save of the same fit in the same place becomes `…_2`, `…_3`; an old `.zip` of that name also counts as taken). Written to `<name>.part` first and renamed; if the contents are identical to the last package written here (fingerprint ignores "Created" DTG lines), nothing new is kept: status *"ExoFOP package unchanged: {folder}"*. If Windows refuses the rename (file still open by antivirus/indexer): warning *"The ExoFOP package is complete in {…}.part but the folder could not be renamed to {name}. Rename it yourself, or save the package again."* Files inside, all prefixed `<planet>_<date>_<obscode>_SHOBS-P`: `_lightcurve.csv` (columns BJD_TDB, rel_flux, rel_flux_err, airmass, detrended_flux, model, residual; first row a `# Created …` line), `_fit.txt` (`tc.fit_text` + `tc.exofop_notes`: equipment from headers/Optics box, pixel scale, aperture, coverage, comp-choice systematic line), `_plot.png` (8×5.4 in at 150 dpi with a "Created … · SHOBS-P x.y" stamp). The AAVSO report is *not* copied in (2.2.17, John's choice). Status after: *"Saved {folder} … Package folder: light curve (CSV), fit and ExoFOP notes (text), and the plot."*
- **"Open ExoFOP…"** — opens the target's ExoFOP-TESS page: by TOI (`target.php?toi=N`), else by TIC id from the lookup or a "TIC nnn" name (`target.php?id=N`), else ExoFOP-TESS home (`exofop_page` L2106, `tc.exofop_ids`). Names come from the Input page planet/star and a loaded report's planet/host. The first click ever (and the first time the home page has to stand in) shows an info box: *"[No TOI or TIC number is known for this target, so ExoFOP-TESS's home page opens: search for the star there.] ExoFOP-TESS is for TESS targets (TOIs and TIC stars) only, and uploading needs an ExoFOP account (log in first). Time series: on the target's page, logged in, choose "Add new" in the Time Series section and upload the light curve (CSV) and fit notes from the ExoFOP package. Files (plot, report): Files "Add new" on the same page, with the same data tag. Data tag: YYYYMMDD_username_description_n (for example 20261015_jsmith_SHOBS-P-transit_1); the description may use only letters, numbers and hyphens."* (remembered in settings `exofop_hint_shown` / `exofop_home_hint_shown`).
- **"Save light-curve CSV…"** — the App's general light-curve CSV (`app.save_csv`, surveyed with the Photometry page); part of the numbered family.
- **"Save plot PNG…"** — `<planet>_<filter>_<date>_SHOBS-P_transit.png` ("Save transit plot PNG" dialog if no output folder). The PNG is the plot (8×5.4 in, 130 dpi) with a header block above it: planet summary, banner or source line, verdict (coloured), quality line, the parameter table (all shown columns), and the notes (minus the on-screen Comp health link), plus a "Created {DTG} · SHOBS-P {version}" stamp (`_write_png` L2002). Error → *"Could not save the PNG: {exc}"*. Works for report fits too.
- **"Variable View  ▶"** (bottom right, accent) — `app.show_variables_view` (clearv_app.py L10382): shows the Variables/photometry Output page for the same data; that page has a matching "Transit View ▶" to come back. Independent of the mode setting.

### 1.8 Planet lookup on the Input page, ephemeris source, χ²ν messages, flip handling

**"Planet (Transits)" group** (clearv_app.py `_page_input` L1705–1737; shown only in Transits mode, `_layout_input_for_mode` L2011):
- "Planet" Entry (`planet_name`). Enter, keypad Enter or leaving the box looks the planet up automatically when the name changed since the last lookup (`_auto_planet_lookup` L1774). "Look up again" Button repeats it (`lookup_planet` L1789). "Tonight's transits…" Button opens the finder (1.9).

**χ²ν messages** (`tc.transit_flags` L1464–1483; thresholds `RCHI2_LOW = 0.5`, `RCHI2_HIGH = 2.0`):
- χ²ν < 0.5 (warn): *"The per-point error bars are about {r}x larger than the real scatter (reduced χ² 0.31). That is the error model, not the data: most often the camera gain (EGAIN missing or wrong in the headers; the photometry log's Photon noise line says what was used), or frames calibrated elsewhere whose values are not camera units. Bad darks, bias or flats would make the scatter larger, not the error bars. The fit keeps the larger error bars, so its uncertainties are on the safe side (too wide)."*
- χ²ν > 2 (info): *"The scatter is about {r}x the per-point error bars (reduced χ² 3.2): noise the error model leaves out, such as thin cloud or dew, tracking or seeing changes (red noise), calibration, or a noisy comp; or a camera gain (EGAIN) too large for the stored values (12/14-bit data scaled to 16 bits; see the photometry log's Photon noise line). The fit scales its error bars up to match, so its uncertainties include it."*
- Other standard cautions (same function): a/R* or b >3σ from published; grazing geometry; free-shape Rp/R* disagrees; *"Little or no baseline before ingress/after egress (N min before, M min after)…"* optionally prefixed *"No usable baseline after egress: the 31 frames there (00:44–01:20) were flagged cloud."*; gap inside transit; ingress/egress not observed; *"Almost no points inside the predicted transit window…"*; step check info; red-noise β>1.5 info; depth vs published info; comp-noise and leave-one-out cautions (link to Comp health).

**Verdict logic** (`tc.transit_verdict` L1191): detected needs ΔBIC ≥ 10 against a flat line (with the flip step when fitted), Tc error ≤ ¼ T14, and a plausible depth (not >3× or <⅓ of published and >3σ off). A jump at a gap that explains the dip as well → inconclusive. Reasons appear verbatim in the verdict line.

**Flip handling** (2.2.13; `FLIP_STEP_ENABLED = False` in 2.2.17 — the flip *step term* is currently disabled, so the "meridian flip at the largest gap" checkbox is hidden and no "Flip step" rows appear unless the constant is re-enabled). When enabled: photometry uses frames' `segment == "flip"`; a report uses its NOTES flip time or the largest gap when the box is ticked; the plot draws a purple dash-dot line with `" flip: step +x.x ± y.y%"`; table rows "Flip step (%)", "Depth without step (%)", "Step–depth correlation"; cautions about baseline on each side of the flip (needs ≥30 min and ≥15 frames per side) and step–depth correlation > 0.9 → "depth not measurable from this night". The report NOTES get the flip time (`tc.flip_report_note`) so a later fit can read it back.

**Pitfalls (Part 1)**: the fit auto-starts when you open the page — press Cancel if you meant to change settings first; Fit transit / Trim / saves are refused while the comp check runs (a few seconds); report fits use the report's planet even if the Input page names another; Trim spans accumulate — use Clear trim to start over; a trim or fit is discarded when photometry is re-run (the series changed); the ExoFOP package is a folder, not a zip, and the AAVSO report is not inside it; without an output folder each save asks where.

### Part 2 pitfalls for new users
- Solve the field before scanning (it happens automatically when the Photometry page is first shown after calibration) — otherwise there are no RA/Dec, no catalog scale, no VSX/SIMBAD check and every candidate is "Unchecked".
- "× normal" is relative to stars of the same brightness, not an absolute amplitude; a 3× candidate with "Check first" text is usually an artifact (saturation, flip, gap).
- Export candidates / all light curves use fixed file names (`field_scan_candidates.csv`, `field_scan_lightcurves.csv`); with an output folder set they get `_2`, `_3` suffixes rather than overwriting.
- Hidden known variables keep their rank numbers, so the table may jump from #1 to #3.
